# 学习开发工作流

## 知识点开发流程

当用户要求实现某个知识点时，按以下步骤执行：

1. **确认知识点编号**：如 "1.3" 表示模块1的第3个知识点
2. **查阅需求文档**：参考 `.kiro/specs/detailed-learning-plan/requirements.md` 中对应知识点的描述
3. **定位目标文件**：根据知识点描述中的「对应文件」字段确定要创建/修改的文件
4. **编写代码**：实现该知识点的功能代码，代码顶部注释标明知识点编号和学习要点
5. **标注面试考点**：在关键代码处用 `// 📝 面试考点：xxx` 标注
6. **不要超出范围**：只实现当前知识点要求的内容，不提前实现后续知识点

## 避免重复工作

- 公共组件（Layout、TabBar、InterviewCard）只在知识点 0.1/0.2 中创建，后续模块直接复用
- `src/services/ai.ts` 只在知识点 0.3 中创建，后续模块的 Hook 直接 import 使用
- 类型定义如果已在其他模块中存在且通用，提取到 `src/types/` 公共目录
- 面试题数据统一在 `src/data/interview-questions.ts` 中维护，按模块追加

## 知识点代码模板

每个知识点的代码文件顶部使用以下注释格式：

```typescript
/**
 * 知识点 1.3：封装 API 调用函数
 * 
 * 学习要点：
 * - fetch 请求头设置
 * - Authorization Bearer Token
 * - 请求体 JSON 序列化
 * - 响应解析
 * 
 * 面试相关：
 * - 如何在前端安全管理 API Key
 * - fetch 与 XMLHttpRequest 的区别
 */
```

## 面试题追加规则

每完成一个知识点的代码后，在 `src/data/interview-questions.ts` 中追加该知识点关联的面试题：
- 每个知识点 1-3 道题
- 覆盖三种类型：principle（原理）、coding（编码）、design（设计）
- 难度分布：junior 30%、mid 50%、senior 20%

## 模块完成检查

一个模块的所有知识点完成后，确认：
- [ ] 所有文件已创建且可正常编译
- [ ] 页面组件已注册到路由
- [ ] 面试题数据已追加
- [ ] 代码中有面试考点标注
