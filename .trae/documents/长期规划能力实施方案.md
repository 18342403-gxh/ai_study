# 长期规划能力 · 实施方案

## Context

当前项目已有 `entries.type='plan'` 的简单规划（一段标题+正文），只能记录，无法根据个人情况生成长期规划，也没有阶段/里程碑/进度。目标：

1. 新增独立「长期规划」实体（新表 `plans`），支持目标、起止时间、进度、阶段/里程碑，并在规划页展示与编辑。
2. 用户可直接在规划页手动新建/编辑规划。
3. 对话里输入「帮我做三个月学习规划」等即可触发 AI 生成；规划页也提供 AI 生成入口。
4. 生成前先通过工具 agent 多步检索知识库（已有条目/文档）：**知识库有相关内容时必须作为规划依据**；知识库没有涉及的部分可以跳过，按通用建议生成，不强行虚构个人情况。追问仅用于「目标本身不明确」（如时间跨度、当前基础），不因知识库缺少内容而追问。
5. 生成结果为可编辑的结构化草稿卡片，确认后入 `plans` 表；草稿基于 LangGraph 检查点，刷新/重启可恢复。

已确认的产品决策：

- 数据层：**新增规划实体**（不复用 entries）。
- 个人情况：**检索 + 追问 1 轮**；检索以知识库为准，知识库未覆盖的部分不参考、按通用建议补足；追问只解决目标歧义。
- 入口：**对话 + 规划页**。
- 确认方式：**草稿卡片，且卡片内可编辑标题/目标/时间/阶段**。
- 历史数据：**双轨展示**——规划页主区读写新表，折叠区展示旧 `type=plan` 条目，支持「转为长期规划」。

## 数据模型

新表 `plans`（SQLite 与 PG 字段同名）：

| 字段                                  | 类型                | 说明                                                   |
| ------------------------------------- | ------------------- | ------------------------------------------------------ |
| id                                    | text/uuid           | 主键                                                   |
| user_id / library_id                  | text                | 默认 local / default                                   |
| title                                 | text                | 规划标题                                               |
| goal                                  | text                | 目标与背景                                             |
| status                                | text                | `draft`/`active`/`done`/`archived`，CHECK 一次性含全量 |
| start_at / end_at                     | integer/timestamptz | 长期起止                                               |
| progress                              | integer             | 0–100，DB CHECK + Zod 双重限制                         |
| stages                                | text/jsonb          | JSON：`PlanStage[]`（title/description/targetAt/done） |
| source_type / source_ref              | text                | conversation / manual / document + 来源 id             |
| created_at / updated_at / archived_at | 时间                | 与 entries 一致                                        |

改动点：

- [schema.sqlite.ts](file:///d:/project/ai_study/apps/server/drizzle/schema.sqlite.ts)、[schema.ts](file:///d:/project/ai_study/apps/server/drizzle/schema.ts) 增加 `plans`。
- [db/index.ts](file:///d:/project/ai_study/apps/server/src/db/index.ts)：新增 `initPlanSchema()`（幂等 CREATE TABLE + 索引），在 `initSqlite()` 中 `initV5Schema` 之后调用；`initPostgres()` 补防御建表。
- `apps/server/scripts/init-pg.sql` 补 `plans` 表与索引。
- 新增 [plan.ts](file:///d:/project/ai_study/packages/shared/src/types/plan.ts)：`PlanStage`、`Plan`、`CreatePlanInput`、`UpdatePlanInput`、`PlanDraft`，并在 `packages/shared/src/index.ts` 导出。`PlanDraft = { title, goal, startAt, endAt, stages, sources: PlanSource[], grounded: boolean }`，其中 `PlanSource = { type:'entry'|'chunk', id, label, snippet }`，`grounded=false` 表示知识库未覆盖、本次为通用建议。
- **不做** plans 向量索引；生成时的个人情况由 entries/documents 检索 + active plans SQL 直查提供。

## 服务端

### 1. plans 存储与 CRUD

新增 `apps/server/src/services/plans/store.ts`：`rowToPlan`（stages JSON 解析）、`listPlans`、`createPlan`、`updatePlan`、`deletePlan`、`insertDraftPlan`、`listActivePlanBriefs`、`convertEntryToPlan`（插入 plans 后把旧 entry 置 `archived`，幂等：源 entry 已转换则返回已有规划）。

新增 [plans.ts](file:///d:/project/ai_study/apps/server/src/routes/plans.ts)，在 `routes/index.ts` 挂载：

- `GET /api/plans?status=&limit=` → `PlanRow[]`
- `POST /api/plans` → 手动新建；body 可选 `fromEntryId` 表示从旧 plan 条目转换
- `PATCH /api/plans/:id`、`DELETE /api/plans/:id`
- `POST /api/plans/generate`、`GET /api/plans/drafts/:threadId`、`POST /api/plans/drafts/:threadId/resume`
- 注意路由顺序：`/generate`、`/drafts/:threadId` 必须定义在 `/:id` 之前。
- 沿用 `validate` + `asyncHandler` + `createError`，handler 内二次 `schema.parse`（中间件不回写）。
- 新增 kill switch `ENABLE_PLAN_AI`（默认开，`==='0'` 关闭）：关闭时 `generate` 返回 409，前端隐藏 AI 入口；手动 CRUD 不受影响。不新增图灰度开关（本链路无旧实现可对比）。

### 2. 工具 agent 复用

- [agent.ts](file:///d:/project/ai_study/apps/server/src/services/tools/agent.ts)：`ToolAgentOptions` 增加可选 `systemPrompt` / `tools`；`resolveToolAgentDeps` 透传；非图循环与图模式的 decide 节点都使用 `systemPrompt ?? TOOL_SYSTEM`。既有调用不受影响。
- 新增 `search_knowledge` 工具（放 `services/tools/` 或 `services/plan/tools.ts`）：入参 `{query, scope:'entries'|'documents'|'all'}`，内部调用 `searchAll({ query, libraryId })`，输出精简文本（≤5 条条目 + ≤3 条文档片段，每条截断 200 字）并标注来源 id；无命中时明确返回「知识库未检索到相关内容」。不加入 `createCommonTools`，只在规划链路注入，避免与对话检索重复。

### 3. 规划生成图

新增 `apps/server/src/services/plan/graph.ts`，复用 `services/graph/runtime.ts` 的 `compileGraph`/`tracedNode` 与 `checkpointer.ts`：

- [thread.ts](file:///d:/project/ai_study/apps/server/src/services/graph/thread.ts) 增加 `planThreadId(draftId)` 与 `plan:` 前缀解析；[types.ts](file:///d:/project/ai_study/apps/server/src/graph) 的 `GraphName` 增加 `plan`（仅用于 trace span）。
- 状态通道命名避免与节点同名：`goal/sessionId/libraryId/nowMs/timezone/draftId/researchNotes/sources/grounded/existingPlans/questions/answers/askRound/planDraft/stage/savedPlanId`。
- 节点：
  1. `research`：读 active plans 摘要 + 调 `runToolAgent`（自定义 `systemPrompt` 与 `search_knowledge`/`get_current_datetime` 工具）多轮检索知识库，产出 `researchNotes` 与命中的 `sources`（条目/文档片段）；无命中时 `grounded=false` 且笔记注明「知识库未覆盖」。`messageId` 用随机 UUID，避免与 `agent:` thread 复用。
  2. `assess`：LLM + 强制工具 `assess_plan_info`（`{needMore, questions≤3}`），只判断**目标本身**是否缺少关键参数（时间跨度、当前基础、可投入时间等）；输入 goal + researchNotes，明确禁止因知识库未覆盖而追问；`askRound>=1` 时直接判定信息足够。
  3. `ask`：`interrupt({kind:'plan_questions', questions, round})`。
  4. `draft`：LLM + 强制工具 `create_plan_draft`（title/goal/startAt/endAt/stages），时间解析沿用 extractor 的 nowMs/timezone 约定；产出 `PlanDraft` 并附带 `sources`/`grounded`。Prompt 硬性要求：知识库命中的事实必须吸收进目标与阶段；未命中的部分使用通用建议，且不得虚构个人经历/偏好/能力；可附带「待补充」条目。
  5. `confirm`：`interrupt({kind:'plan_draft', draft})`。
  6. `save`：`insertDraftPlan`（`sourceType='conversation'`, `sourceRef=sessionId`）。
  7. `finish`：空节点。
- 边：`START→research→assess`；`assess→ask | draft`；`ask→assess`（resume 后 askRound+1）；`draft→confirm`；`confirm→save | finish`；`save→finish`。
- thread：`plan:{draftId}`；编译开启 checkpointer，模块级缓存并提供 `resetPlanGraph()`；支持注入 `research` 与 `invoke` 便于测试（参考 [extract/graph.ts](file:///d:/project/ai_study/apps/server/src/services/extract/graph.ts)）。
- 坑：节点名不得与状态字段同名；`interrupt` 节点外层禁止 try/catch；resume 前用 `graph.getState()` 校验当前中断类型，不匹配返回 400；检查点不存在返回 404。

### 4. 接口契约

`PlanStepResponse`：

```ts
{
  ok: true
  threadId: string
  draftId: string
  stage: 'ask' | 'confirm' | 'done'
  questions?: string[]
  draft?: PlanDraft
  savedPlan?: PlanRow
  done: boolean
}
```

- `POST /api/plans/generate` `{ goal, sessionId?, libraryId? }`
- `POST /api/plans/drafts/:threadId/resume`
  - 追问阶段：`{ answers: string[] }`
  - 确认阶段：`{ action: 'confirm', draft: PlanDraft }`（卡片编辑后回传）或 `{ action: 'discard' }`
- `GET /api/plans/drafts/:threadId` → 恢复用，返回同上结构（含 `questions`/`draft`）。

## 前端

### 1. 类型与请求

[utils/api.ts](file:///d:/project/ai_study/apps/generator/utils/api.ts) 增加 `PlanStage`、`PlanRow`、`PlanDraft`、`PlanStepResponse`、`PlanDraftResponse`，复用 `apiGet/apiPost/apiPatch/apiDelete`。

### 2. 组件

- `components/PlanForm.vue`：受控表单，字段 title / goal / startAt / endAt / progress / stages（阶段行支持增删、完成勾选、目标时间）。PlanEditor 与 PlanDraftCard 共用。
- `components/PlanEditor.vue`：弹窗，内部用 PlanForm；`entry` 为空表示新建，否则编辑；保存调用 POST/PATCH `/api/plans`。
- `components/PlanDraftCard.vue`：展示 AI 草稿，内部持有 PlanForm 副本，支持编辑后「确认入库」「放弃」；确认调用 resume。顶部显示依据：`grounded=true` 时列出 `sources` 数量与前几条来源标题；`grounded=false` 时提示「知识库未覆盖，以下为通用建议」。

### 3. 规划页 [plans.vue](file:///d:/project/ai_study/apps/generator/pages/plans.vue)

- 主区改为 `GET /api/plans?status=&limit=500`：卡片显示标题、目标摘要、起止时间、进度条、阶段完成数；展开查看阶段；操作沿用完成/搁置/恢复/编辑/删除。
- 顶部新增「AI 生成规划」（`ENABLE_PLAN_AI` 关闭时不显示）与「新建规划」。
- AI 面板：输入目标 → `generate`；追问阶段展示问题 + 回答框（再次 resume）；草稿阶段展示 PlanDraftCard；确认后刷新列表。进入页面读取 `ai-study:pending-plan` 并 `GET /drafts/:threadId` 恢复。
- 折叠区「旧版规划」：`GET /api/entries?type=plan&status=` 展示旧条目（标题/正文/来源），每条提供「转为长期规划」→ `POST /api/plans { fromEntryId }`，成功后刷新两块列表。

### 4. 对话页 [chat.vue](file:///d:/project/ai_study/apps/generator/pages/chat.vue)

- 新增规划意图正则（规划/计划/路线/方案/目标拆解/未来 N 个月/半年/年度等组合），命中且无待处理规划草稿时，走 `POST /api/plans/generate` 而不是 `/api/chat`。
- 追问阶段：助手消息展示问题，`localStorage['ai-study:pending-plan'] = {threadId, stage:'questions'}`；用户下一条输入作为 `answers` 调 resume（不再走普通 chat）。
- 草稿阶段：消息流内渲染 `PlanDraftCard`，确认/放弃调 resume，完成后清除 localStorage。
- 进入页面 `GET /drafts/:threadId` 恢复未完成规划（参照现有抽取草稿恢复逻辑）。
- 不命中规划意图时行为完全不变。

- 单测 `services/plan/__tests__/graph.test.ts`（临时 SQLite + 动态 import，模式同 extract 图测试）：条件边纯函数；追问→回答→草稿→确认→`plans` 落库；discard 直接结束；`closeCheckpointer + resetPlanGraph + 重开 DB` 后凭 threadId 恢复；**知识库无命中时仍直接产出草稿（`grounded=false`，不触发追问）**。
- 单测 `services/plans/__tests__/store.test.ts`：CRUD、progress/stages 校验、`convertEntryToPlan` 幂等与旧条目归档。
- 校验：`pnpm --filter @ai-study/server typecheck`、`pnpm --filter @ai-study/server test`、`pnpm --filter @ai-study/generator typecheck`、`npx eslint` 相关文件。
- 手工 E2E（dev 已运行）：
  1. 规划页新建/编辑/完成/搁置/删除长期规划。
  2. 对话输入「帮我做一个三个月学习规划」→ 出现追问 → 回答 → 出现可编辑草稿 → 修改标题/阶段 → 确认 → 规划页出现。
  3. 知识库无相关内容时（例如冷启动库）：不追问，直接生成通用建议草稿，卡片明确提示「知识库未覆盖」。

  5. 旧版规划区展示历史 `type=plan` 条目，可一键转换。
  6. 关闭 `ENABLE_PLAN_AI=0` 时 AI 入口消失、手动功能正常。
