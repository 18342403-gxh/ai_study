# 登录、账号与知识库隔离实施计划

## Context

当前所有访问者共用同一个知识库：接口的 `libraryId` 全部由前端传参且默认 `"default"`，`sessions` 表没有归属字段，文档向量/BM25 检索也不按知识库过滤。需求是引入登录能力，把知识库按账号隔离：

- **超管账号**：可正常使用自己的知识库，并可生成、查看、提前删除临时账号。
- **临时账号**：由超管在账号生成页创建，有效期 1 天；拥有独立知识库；到期或删除时知识库级联销毁。
- 已确认的取舍：
  1. 临时账号交付方式：**用户名 + 随机密码**（生成后展示一次，可复制）。
  2. 超管初始化：默认 `admin / admin129`，密码写在配置/环境变量中，**数据库只存哈希**。
  3. 存量数据：归入超管知识库（超管 `id=local`、`library_id=default`），无需迁移。

## 一、数据层

### 1. `apps/server/scripts/init-pg.sql`

幂等新增：

- `app.users`
  - `id VARCHAR(64) PRIMARY KEY`（超管固定 `local`，临时账号为 UUID）
  - `username VARCHAR(64) UNIQUE NOT NULL`
  - `password_hash TEXT NOT NULL`（scrypt，格式 `salt:hash`）
  - `role VARCHAR(16) NOT NULL CHECK (role IN ('admin','temp'))`
  - `library_id VARCHAR(64) NOT NULL`（超管 `default`，临时账号等于自身 id）
  - `status VARCHAR(16) NOT NULL DEFAULT 'active' CHECK (status IN ('active','deleted'))`
  - `expires_at TIMESTAMPTZ`（超管 NULL）
  - `created_by VARCHAR(64)`、`last_login_at TIMESTAMPTZ`、`created_at`、`updated_at`
- `app.auth_sessions`（避免与聊天 `sessions` 表重名）
  - `id UUID PK`、`token_hash VARCHAR(64) UNIQUE NOT NULL`、`user_id VARCHAR(64) REFERENCES app.users(id) ON DELETE CASCADE`
  - `expires_at`、`user_agent`、`ip`、`created_at`
  - 索引：`user_id`、`expires_at`
- `app.sessions` 增加 `user_id VARCHAR(64) NOT NULL DEFAULT 'local'` 与索引。
- 数据索引：`documents(library_id)`、`sessions(user_id)`。

### 2. `apps/server/drizzle/schema.ts`

新增 `users`、`authSessions` 表定义；`sessions` 增加 `userId`。

### 3. `apps/server/src/db/index.ts`

`REQUIRED_TABLES` 增加 `users`、`auth_sessions`。

## 二、认证与账号服务

新增 `apps/server/src/services/auth/`：

- `password.ts`：Node `crypto.scrypt` + 随机盐哈希、`timingSafeEqual` 校验，不引入新依赖。
- `session.ts`：
  - 生成 32 字节随机 token；数据库只存 `sha256(token)`。
  - Cookie 名 `ais_session`，`HttpOnly`、`SameSite=Lax`、`Path=/`；生产 https 时 `Secure`。
  - 超管有效期 7 天；临时账号取 `min(7天, 账号 expires_at)`。
- `users.ts`：
  - `ensureAdmin()`：启动时若不存在超管，则用 `ADMIN_USERNAME`（默认 `admin`）与 `ADMIN_PASSWORD`（默认 `admin129`）创建 `id=local / library_id=default` 的超管；已存在则不覆盖密码。
  - `createTempUser()`：用户名 `temp-` + 6 位小写字母数字，12 位随机密码；24 小时有效；返回明文密码一次。
  - `listTempUsers()`、`findUserByUsername()`。
- `purge.ts`：销毁账号并在事务内清理其知识库，见第四节。

新增中间件 `apps/server/src/middleware/auth.ts`：

- `authenticate`：解析 Cookie → 查 `auth_sessions` + `users` → 校验账号 active、未过期；临时账号过期时先触发销毁再返回 401；把 `{ id, username, role, libraryId, expiresAt }` 挂到 `req.authUser`。
- `requireAdmin`：非超管返回 403。
- 放行路径：`/api/health`、`/api/auth/login`、`/api/auth/logout`。
- 补 Express 类型声明（`src/types/express.d.ts`）。

新增路由：

- `apps/server/src/routes/auth.ts`
  - `POST /api/auth/login`：用户名 + 密码校验，写登录态、种 Cookie。
  - `POST /api/auth/logout`：删除当前登录态、清 Cookie。
  - `GET /api/auth/me`：返回当前账号。
- `apps/server/src/routes/admin.ts`（均 `requireAdmin`）
  - `GET /api/admin/users`：临时账号列表（用户名、创建时间、到期时间、状态）。
  - `POST /api/admin/users`：生成临时账号，响应仅此一次包含明文密码。
  - `DELETE /api/admin/users/:id`：提前销毁账号及知识库。

`apps/server/src/index.ts`：CORS 增加 `credentials: true`；挂载认证中间件与两组新路由；`/api/logs`、`/api/cost`、`/api/metrics`、`/api/logs-view` 改为仅超管可访问；启动时调用 `ensureAdmin()` 与过期账号定时扫描（60s）。

## 三、租户隔离（服务端强制，不信任前端传参）

统一规则：**所有接口忽略客户端 `libraryId/userId`，改用 `req.authUser.libraryId / id`；按 id 访问的资源必须同时匹配当前 `libraryId`（会话匹配 `userId`），否则 404。**

逐路由改造：

- `routes/chat.ts`：`libraryId` 取登录态；`sessionId` 归属当前用户才允许写历史。
- `routes/sessions.ts`：补 `user_id` 写入；列表/详情/更新/删除/追加消息全部按 `userId` 过滤。
- `routes/extract.ts`：`libraryId`、`userId` 取登录态；失败草稿落库写当前 `userId`；`GET/续跑`草稿先读状态并校验 `libraryId`。
- `routes/documents.ts`：列表、上传、重新解析、删除、文档抽取全部按文档 `libraryId` 过滤；上传写入当前 `userId/libraryId`；`recoverStaleProcessing()` 只处理当前库。
- `routes/entries.ts`：列表强制当前 `libraryId`；新建强制 `userId/libraryId`；详情/更新/删除校验归属；禁止通过 PATCH 改库。
- `routes/plans.ts` 与 `services/plans/store.ts`：列表强制当前库；新建/草稿入库写入当前 `userId/libraryId`；详情/更新/删除校验归属；`listActivePlanBriefs` 增加库过滤。
- `routes/reminders.ts`、`routes/search.ts`、`routes/kb.ts`、`routes/rag.ts`：取登录态库；RAG 查询传给 `searchAll`。
- `services/extract/graph.ts`：状态增加 `userId`，`commit` 落库与失败草稿不再写死 `'local'`。
- `services/search/graph.ts`：文档通道传 `options.libraryId`。
- `services/search/docChannel.ts` → `services/rag/index.ts` → `vectorStore.ts / bm25.ts`：
  - `searchDocumentsSemantic(query, k, queryType, libraryId)` 增加库参数。
  - `createRAGService().search(...)` 与 `similaritySearch / bm25Search` 增加 `libraryId`，查询时 `INNER JOIN app.documents` 并过滤 `library_id`、排除已删除文档。
- `routes/logs.ts / cost.ts / metrics`：仅超管。

> 前端仍可继续传 `libraryId`，服务端一律覆盖，避免把隔离责任放到客户端。

## 四、账号销毁与知识库级联清理

`services/auth/purge.ts` 的 `purgeUser(userId)`：

1. 读出该账号 `library_id` 下所有 `documents.storage_path`，先尽力删除本地文件（URL 导入的跳过，文件不存在忽略）。
2. 单事务删除：
   - `documents`（`chunks` 由外键级联）
   - `entries`（`entry_embeddings` 级联）
   - `plans`
   - 聊天 `sessions`（`messages` 级联，按 `user_id`）
   - `ai_usage_logs`（按 `user_id`）
   - `auth_sessions`（按 `user_id`）
   - `users` 行
3. 触发时机：超管手动删除、临时账号到期后的首次访问、后台 60s 定时扫描。
4. 临时账号的 LangGraph 草稿线程不做额外清理（无法再访问，且不属于知识库数据）。

## 五、前端

- `apps/generator/utils/api.ts`
  - 所有请求加 `credentials: 'include'`。
  - SSR 时通过 `useRequestHeaders(['cookie'])` 透传 Cookie（用 try/catch 兼容非 setup 上下文）。
  - 401 统一跳转 `/login`（登录接口自身除外）。
- 新增 `apps/generator/middleware/auth.global.ts`
  - `/login` 放行；其他页面请求 `/api/auth/me`，失败跳登录。
  - `/admin/**` 要求 `role === 'admin'`，否则回 `/chat`。
- 新增 `apps/generator/pages/login.vue`
  - 用户名/密码表单，调用 `/api/auth/login`，成功后跳 `/chat`；`definePageMeta({ layout: false })`，使用现有 Tailwind 风格。
- 新增 `apps/generator/pages/admin/accounts.vue`
  - 生成账号按钮、生成结果（用户名 + 密码 + 复制）、临时账号列表（剩余时间、删除）。
- `apps/generator/layouts/default.vue`
  - 底部展示当前用户名、角色、临时账号剩余时间（倒计时）、退出登录。
  - 超管额外显示“账号管理”入口。
- `pages/chat.vue`、`pages/plans.vue` 中写死的 `libraryId: 'default'` 清理掉（服务端不再使用该值）。

## 六、配置

- `apps/server/.env.example` 与生产配置增加：
  - `ADMIN_USERNAME=admin`
  - `ADMIN_PASSWORD=admin129`
  - `TEMP_ACCOUNT_TTL_HOURS=24`
  - `AUTH_SESSION_TTL_DAYS=7`
- `docker-compose.prod.yml` 的 server 服务透传上述变量；`.env.prod` 写入默认值（数据库仍只存哈希）。
- 首次启动自动建超管；已有超管不覆盖密码。

## 七、验证

1. 执行 `pnpm --filter @ai-study/server db:init`，确认新表/字段创建成功。
2. `pnpm --filter @ai-study/server typecheck`，并运行现有 `pnpm --filter @ai-study/server test`。
3. 本地启动 BFF 与 generator：
   - 未登录访问 `/chat` → 跳 `/login`。
   - `admin/admin129` 登录 → 能看到现有文档/记录（归属 `default`）。
   - 生成临时账号 → 退出 → 用临时账号登录 → 文档、条目、会话均为空；上传文档后仅临时账号可见。
   - 超管登录后看不到临时账号文档；临时账号访问 `/admin/accounts` 被拒。
4. 隔离验证：
   - 临时账号 A 上传文档，临时账号 B 检索不到（向量与 BM25 均验证）。
   - 直接 `curl` 传别人的 `libraryId` 或资源 id → 被服务端覆盖或返回 404。
5. 生命周期验证：
   - 超管提前删除临时账号 → 账号立即失效，文档/条目/规划/会话被清理，上传目录文件被删除。
   - 将账号 `expires_at` 手动改为过去时间 → 再次访问返回 401，数据被清理。
6. 生产部署：复用 `ai-study-deploy` 技能，部署后验证 `/api/health`、登录、账号生成、隔离。
